NBI Experiment PortalImplementation & Experiment Guide
Based on “Notification Burden Index – Eye Tracking Study Protocol”, Pilot v1.1, 23 September 2026
Purpose. This document translates the study protocol into a clear portal workflow: what the participant sees, what the researcher controls, the exact default timings, how N/L/H notifications are scheduled, and what data must be stored for eye-tracking synchronization and later analysis.
Important: The protocol repeatedly labels several durations/counts/windows as pilot settings. The portal should therefore use the protocol values as defaults while allowing researcher-controlled, versioned changes. Every completed session must retain the exact configuration used.

2. Portal Roles
Participant mode
Distraction-free, full-screen task interface.
Shows only instructions and stimuli needed for the current task.
Never exposes condition codes (N/L/H), task-order cell, passage mapping, notification variant, message IDs/categories, pseudo-events, seeds, analysis windows, or answer keys.
No correctness feedback in scored Stroop or comprehension phases.
Researcher/Admin mode
Create participant/session using participant code; record tracker/calibration metadata, sleep hours, testing time, unusual fatigue and deviations.
Auto-balance or manually select task-order cell, passage mapping, notification variant and L timing choice.
Edit protocol defaults through versioned configuration; changes apply to future sessions, not completed sessions.
Run calibration/drift-check gates, extra breaks/recalibration and controlled abort/skip actions with required reason.
View/export session logs and quality-control summaries.

For each participant, draw six independent jitter values from −5 to +5 s, one per candidate.
Reuse the same six-value jitter vector in all three reading conditions for that participant.
H uses all six candidates. L uses either the three earlier candidates or the three later candidates, balanced across participants. N logs all six as invisible pseudo-events.
If a candidate falls within 5 s after a panel change, delay only until the panel has been stable for 5 s; maximum extra delay 5 s. Apply the same rule to pseudo-events.
Maintain at least 20 s between actual event onsets and at least 10 s of reading after each onset. If constraints fail, mark the event missed; do not compress later events.
Store scheduled and actual onset/offset. The analysis metadata window begins at −5 s and ends at +10 s around actual onset; flag panel transitions inside the window.
Banner appearance
Use exact Appendix C messages. Internal IDs/categories are stored but not shown.
Header: “Study notification”. Silent visual banner, 3,000 ms default duration, fixed region beside text.
No animation, vibration, badge, logo, countdown, reply button or click target.
Use consistent neutral appearance and never cover the text.
Never show notifications during baseline, Stroop, comprehension or breaks.
7. Comprehension, Ratings and Breaks
Comprehension
After each reading block, hide the passage and show all 3 multiple-choice questions together for 60 s.
Accept one A/B/C/D response per question; unanswered items are omissions.
No feedback until the study ends; score 1 point per correct answer.
Answer keys must remain researcher-only.
Store responses, timestamps, correctness, omissions, content-display coverage, last panel and progress.
State ratings
Mental fatigue item: “How mentally tired do you feel right now?” Use a 0–10 scale from “not at all” to “extremely”, before active block 1 and after each active block.
After each reading block also collect experienced distraction and difficulty returning to reading. The protocol does not specify their exact scale or anchors, so the portal must make these researcher-configurable rather than silently inventing a scale.
Breaks
Three standard breaks of 120 s, between the four active blocks.
Participant may rest eyes/adjust posture but should not use a phone.
Final 30 s uses the same neutral screen for readaptation.
Researcher completes a drift check before the next active block; extra breaks/recalibration are logged.

11. Portal Fidelity / QA Checklist
Stroop = exactly 120 scored trials and 300 s by default; each trial 500/1500/500 ms.
Early Stroop response never shortens display; no scored feedback.
Reading = exactly 300 s and questions = 60 s by default.
N: 0 visible banners + 6 pseudo-events; L: 3 visible; H: 6 visible.
Same jitter vector reused across N/L/H for the participant.
Notification default duration = 3,000 ms; text is never obscured.
No notifications outside reading blocks.
Three reading blocks remain together; assigned N/L/H order and passage mapping are preserved.
Three 2-min breaks only between active blocks; final 30 s neutral screen; drift check before next block.
All seeds, generated orders, actual timestamps and protocol-version snapshot are saved.
Participant mode hides all internal research codes and answer keys.
12. Researcher: How to Run One Participant
Create a new session and enter participant code, tracker details, previous-night sleep, testing time and unusual-fatigue notes.
Confirm/auto-generate task-order cell, passage mapping, notification variant, L timing choice and seeds. Do not tell participant the internal allocation.
Complete consent/instructions outside or inside the approved portal workflow; calibrate and validate the eye tracker; mark the checkpoint complete.
Run Stroop practice and reading practice. Resolve any practice misunderstanding before baseline.
Start 5-minute baseline. Then collect the initial mental-fatigue rating immediately before active block 1.
Run the four active blocks exactly in assigned order. After each reading: 60-second comprehension, then reading-specific ratings. After every active block: mental-fatigue rating.
Between active blocks run the 2-minute break; final 30 seconds neutral screen; perform drift check and recalibrate if necessary.
After the last block, debrief and record any deviations, missed notifications, extra breaks or recalibration.
Complete the session record, verify data completeness, and export synchronized task logs for later eye-tracking merge/analysis.
13. Implementation Notes That Protect the Experiment
Use a client-side state machine and monotonic timing; save actual rendered onsets/offsets rather than trusting scheduled timers.
Autosave during the session and recover only with researcher confirmation after accidental refresh/crash.
Prevent key-repeat from generating multiple panel moves/responses; log invalid keys.
Add a clearly separated accelerated simulation/test mode. Test data must never be mixed with real sessions.
Keep content in configuration/seed files, not hard-coded across UI components, so pilot revisions are controlled and traceable.
Run automated validators for Stroop matrix totals, event counts, notification spacing, task allocation and missing fields before allowing a scored session to be marked complete.
